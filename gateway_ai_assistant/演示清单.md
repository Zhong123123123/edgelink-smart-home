# 演示 Checklist

## 演示前

- 启动 FastAPI：
  ```bash
  python3 -m uvicorn gateway_ai_assistant.app:app --host 127.0.0.1 --port 8010
  ```
- 启动 Streamlit：
  ```bash
  python3 -m streamlit run gateway_ai_assistant/streamlit_app.py
  ```
- 如需验证回归：
  ```bash
  python3 -m unittest discover -s gateway_ai_assistant/tests -v
  ```
- 确认页面可打开
- 确认 `总览` 页指标正常显示
- 确认有可用固件 `firmware_id`

## 5 到 8 分钟演示顺序

### 1. 总览

- 打开 `总览`
- 讲待审批、批量执行中、开放工单、报告总数
- 如果需要，补一句：当前诊断报告页已经能看到 Multi-Agent 采集轨迹

### 2. 问答

- `DEVICE_001 当前状态正常吗？`
- `最近 OTA 失败任务变多，结合文档分析可能原因`

### 3. 批量 OTA

- 去 `Workflow 演示 -> 批量 OTA`
- 输入 `1,2,3`
- 点击 `生成批量计划`
- 点击 `创建批量审批`
- 点击 `批准并执行批量下发`
- 记录 `approval_id` / `batch_run_id`

### 4. 批量执行治理

- 去 `治理中心 -> 批量执行中心`
- 输入 `batch_run_id`
- 点击 `加载批量执行详情`
- 点击 `刷新任务进度`
- 点击 `启动下一批`
- 可选：点击 `暂停批量推进`
- 可选：点击 `终止后续批次`

### 5. 诊断与工单

- 去 `Workflow 演示 -> 诊断与报告`
- 点击 `执行规则诊断`
- 点击 `生成报告`
- 点击 `根据当前报告创建工单`
- 去 `治理中心 -> 工单中心`
- 演示筛选 / 指派 / 关闭 / 重开

### 6. Agent

- `请对 device_ids=1,2,3 做批量 OTA 风险检查并创建审批 firmware_id=fw-1`
- `请启动下一批 OTA batch_run_id=batch-run-xxx operator=tester`
- 可选：`请暂停批量 OTA batch_run_id=batch-run-xxx operator=tester`
- 可选流式：`请给设备 1 升级固件 fw-1`

## 必讲点

- 这是在真实嵌入式网关系统上扩出来的，不是空白 demo
- 文档、SQLite、OTA、日志都接入了
- 模型不直接拿数据库执行权，SQL 是受控模板
- 批量 OTA 是分批推进，不是一次性群发
- 所有关键治理动作都有审批/审计/轨迹
- LangGraph Agent 支持 `stream` 和 `resume`，不是只有同步执行
- 诊断与故障报告已经接入只读 Multi-Agent `DiagnosisTeam`

## 可能翻车的点

- 没有配置真实 LLM key 时，回答会退化成 mock，但流程依然能演
- 如果 OTA 任务状态数据不足，先重点演治理流程和状态机，而不是强调底层升级结果
- 如果批量执行详情为空，先从 `Workflow 演示 -> 批量 OTA` 重新创建一轮审批和执行
- 如果串口不可用，串口 OTA 会被 assistant 主动拦住；演示时可切到 `tcp_binary` / `mqtt` 或先只展示审批与治理闭环

## 演示后收尾一句

这个项目的重点不是“把大模型接进来”，而是把大模型能力放进受控的嵌入式运维框架里，让它既能问、能查，也能通过 LangGraph Agent 参与审批和批量 OTA 治理。
